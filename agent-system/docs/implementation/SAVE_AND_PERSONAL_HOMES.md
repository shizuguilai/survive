# 营地存档与个性住宅

## 操作

世界变化时每10秒自动存档；完整模型批次提交时按同一10秒间隔触发后台保存，发布规划、暂停、停止、应用运行设置、切到后台时立即尝试保存。底部只在写入完成后更新最近保存时间，失败则显示原因。「运行设置」内有「保存进度」「读取存档」，手动保存可立即重试。

重新进入会自动恢复最近的完整营地，停在原来的模拟时间，点击「继续营地」才运行。不会把离线时长算进饥饿、精力、天气或施工。停止后再次开始也继续当前营地；只有「新营地（重置）」主动新建世界并开始保存新进度。

这是同设备、同浏览器的本机存档，不跨设备或浏览器同步。清除站点数据会删除存档；没有保存成功的进度不能凭空恢复。

## 保存和恢复边界

- 保存完整世界：随机状态、时间、资源、仓储、住处与家具、建造与改建工程、居民身体状态、装备、个人物资、私人记忆、已知引用、地图记忆、已产生的声音和正在执行的动作进度。
- 保存尚在观察者队列中的规划、运行模式、选中的居民和感官显示。视角/屋顶等纯观察设置继续使用原有独立设置，不参与模拟。
- 两个存储槽轮流写入，带版本、递增序号、时间和完整性校验；一份损坏时读取另一份，空间不足或权限错误时保留上一份完整存档并显示失败原因。
- 连续保存复用已验证的槽位/序号，不再反复解析两份旧世界；新快照仍完整校验，只有持久化成功才更新游标，读档时重新核对存储内容。
- 网页使用 IndexedDB 存放完整快照，浏览器支持时使用 gzip 无损压缩；事务完成后才算保存成功。旧 localStorage 存档会先校验、迁移、读回核对，再删除已确认备份且未被其他页面修改的对应旧槽；损坏原件、旧版检查点和无关站点数据保留。数据库不可用时兼容原双槽存储，微信小游戏继续使用原存储接口。
- 全部居民的模型答复仍作为完整批次原子提交，模型思考期间全世界冻结。网页存档属于异步观察者设施，不阻塞批次提交；存档失败只显示提示，不再误报认知失败或冻结营地。退出时尚未提交的部分模型答复不存为决定，恢复后重新请求整个需要决策的批次。
- 感官采样时低频清理旧原始观测，保留最近256条及所有文字记忆、当前/挂起计划、上次决定引用的证据。全部文字记忆、私人地图、已知目标和观测序号保留，不因清理重复使用旧引用；保存本身不会修改现场。
- 两份都损坏时保留原数据并暂停自动覆盖；用户可手动「保存进度」使用当前营地。合法但过期的旧版 `survive_agent_commit_v1` 可按世界哈希校验恢复，原检查点保留。此恢复最多找回当时最后一次已提交决策的现场，之后的未存进度无法找回。
- 不保存 API key、网关令牌、Cookie 或半成品模型答复。格式校验与校验和用于识别数据损坏，不是防作弊或密码学认证。

## 每个人的住宅

新住宅以居民的稳定住房偏好选择样式，同一个居民在读取存档或扩建后保持风格；没有每帧重新随机外观。所有模型继续使用 LayaAir 原生几何。

| 居民 | 样式 | 一级占地 | 木材 / 石料 | 主要外观 |
|---|---|---|---|---|
| 阿林 | 杉木小屋 | 4 × 3 | 12 / 8 | 木墙、草绿屋顶 |
| 小禾 | 暖瓦平房 | 4.8 × 3.6 | 17 / 12 | 浅墙、暖红瓦、横向屋脊 |
| 阿岚 | 灰瓦长屋 | 3.6 × 4.4 | 16 / 11 | 较深长屋、蓝灰陡屋顶 |
| 小川 | 青檐宽屋 | 5 × 3.8 | 18 / 12 | 较宽平面、青绿屋檐 |
| 阿青 | 砖红小筑 | 3.6 × 3 | 12 / 8 | 紧凑平面、砖红色 |
| 小麦 | 浅墙雅舍 | 4.4 × 4.2 | 18 / 12 | 浅墙灰瓦、接近方形 |

屋顶坡度、方向、窗板、木地板和被褥颜色不同，床、柜、灯、拖把按住宅布局摆放。休息动作与渲染共用同一床位，居民从实际房门进出。点击房屋显示样式和真实占地；居民生活详情可看住房偏好。

扩建继续保留该户样式，各户长宽增长量不同。先备足各自配方、检查居住区空地并预留扩建地块，再拆旧回收；原家具、柜内物资保留。不同大小的住宅采用细格选址，互相检查实际占地和出入口通路，不能覆盖邻居或抢占已预留的扩建位置。

旧住宅保留原有占地与家具位置，已保存的睡眠动作不会被移动床位打断；外观可按房主着色。未记录样式的旧项目继续沿用旧尺寸和建材配方，避免读档时追加材料或扩大碰撞范围。

## 验证

- 存档超限修复：`camp-storage.test.ts` 验证数据库双槽、旧档迁移、校验失败回退、读取超时、超大私人状态和异步快照；`camp-controller.test.ts` 验证保存失败时完整批次仍提交、10秒限频、手动恢复及新旧营地竞态；`observation-retention.test.ts` 验证清理前后模型上下文完全一致、证据链和私人状态保留、序号不重用。
- 浏览器复现脚本 `tools/verify-save-quota-ui.mjs` 使用隔离的桌面/手机尺寸 Chromium 上下文，实际填满 localStorage，检查 IndexedDB 迁移、成功保存/重载，以及数据库不可用时不中断模拟并保留最后成功存档；结果见 `evidence/save-quota-ui.json`。这是浏览器仿真测试，不代表实体手机或断电恢复验收。
- 正常4居民本地算法营地运行至 tick 11739 时，未清理的观测约占世界 JSON 的75.2%；单份约226万 UTF-8字节，gzip后约13.6万字节。双槽按 UTF-16约733万字节，另有观察者档案，解释了原同步存储超限。该测量是复现场景，非用户存档的实际体积，数据见 `evidence/save-size-audit.json`。
- `npm test`：182项，181通过，1项可选30秒冻结测试未运行。包括存档完整往返、损坏回退、写入失败、旧检查点、半批模型中断、部分采集连续性，以及实际控制器的保存、读取、自动保存、停止继续和后台冻结。
- 六户不同占地的真实施工结算、不同布局的床位与墙体边界、扩建预留与物资保留、原生屋顶/材质/家具节点均有回归测试。
- `node tools/verify-save-homes.ts`：明确的 `LOCAL_ALGORITHM`，0次远程调用，在tick 915施工中保存并重建模拟，动作进度一致；至tick 8637完成两间不同尺寸的住宅，最终存档世界哈希与现场相同。途中两次仓储材料不足会正常中止该动作，补料后完成，没有虚构材料。
- `npm run typecheck` 与 `npm run build`；产物和完整日志随本次版本保留在 `evidence/save-homes-*`。

早期住宅验收中的控制器和节点测试采用测试环境替身；上述182项是该轮记录，不是当前完整测试集数量。存档超限修复另有真实 Chromium 渲染与存储验收。本轮未进行实时远程模型、浏览器断电/崩溃、LayaAir IDE 或微信真机恢复验收；更早项目格式转换、云端跨设备存档仍未实现。
