# 本地连续执行与居民聚焦

## 操作与边界

左侧详情栏点击居民或「下一位」时，镜头把该居民头部置于面板之间的可见地图区域，保留现有缩放和旋转。重复点当前居民可再次定位；定位后可以继续手动拖动地图，不会被持续跟随拉回。地图直接点选仍保持点击位置，方便重叠居民轮选。地图边缘继续受相机边界约束。

明确选择「本地算法」后，本地规划不进入模型等待状态，不重设模拟时钟，也不为一次决定反复复制、哈希整个世界。先校验该批全部意图，在同一同步调用内一起发布居民动作。只给需要后续动作的居民重新规划，其他居民继续已有队列；远程模型思考时的全局冻结规则保留。

农事可以预排「开垦→播种→浇水」或「走到水边→取水→返回田块→浇水」。这些只是意图，不提前扣水、改变地块或增加收获；每一步仍由动作执行器检查距离、地块状态和物资。条件发生变化时中止受阻动作，再按实际反馈规划。

本地异常显示为「本地规划异常」，重试直接调用本地规划，不请求模型网关。已有营地保留，不会为了恢复而新建营地。

## 已知目标数量

原先把所有私人已知目标直接放进请求，而协议最多允许128项。大地图探索和农田地块增长后会触发 `knownTargets: array length outside range`。

现在由上下文选择器在同一协议预算内选择本次需要的目标，优先保留当前/挂起动作引用、自身装备、已知营地设施、近期观测及完整证据链，再补充任务、可见和邻近目标。上下文中的地图地标引用同步筛选。历史地图、全部已知目标和文字记忆仍留在居民自身状态里，不删改长期记忆，不增加未经感知的知识。

## 保存开销

营地保存继续捕获不可变的完整快照、校验新状态、无损压缩并等待数据库事务完成。相邻保存沿用已验证的双槽序号与槽位，不再重复解析两份旧快照；只有写入成功后才提交新的游标，失败保留上一份完整存档。

## 验证

针对上下文预算、证据引用、相机旋转与遮挡、本地整批提交、提前排队动作、存储失败与远程冻结分别做回归。浏览器脚本 `tools/verify-local-smooth-ui.mjs` 使用明确的成熟营地测试场景、真实本地算法与Laya界面，记录改前/改后耗时、长期探索报错及桌面/手机尺寸选人定位；数据见 `evidence/local-smooth-ui.json`。

新增 `context-budget.test.ts` 覆盖500个私人目标、完整摘要证据链、耗尽的个人物资及大量旧目标的真实本地执行；`local-planning.test.ts` 覆盖零整世界复制、连续时钟、完整批次校验、本地重试、真实农事耗时和条件变化；`camp-controller.test.ts` 另验证本地重试不访问网关。相机、旧存档、农业、远程屏障和私人地图相关回归通过。

性能数据来自桌面环境中的 Chromium 与软件渲染，手机尺寸表示触屏视口仿真，不是实体手机帧率或实时远程模型验收。

本轮同一成熟营地桌面场景约12秒测量：旧版5次长任务，共1835毫秒，最大435毫秒；新版只记录到1次72毫秒的启动长任务，连续规划不再反复出现半秒停顿。新版局部规划期间整世界哈希和复制调用均为0。手机尺寸大目标场景从原先 tick 11739 报错暂停，改为推进到 tick 11980；四人的私人已知目标仍为180/174/175/175项，请求各128项。两种视口共18次实际指针选人，覆盖0°、45°、90°旋转、边缘限制及定位后拖动；无远程请求、页面错误或缺失资源。
