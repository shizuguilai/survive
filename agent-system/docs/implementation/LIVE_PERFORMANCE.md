# 在线性能与回放移除（PERF01）

## 原因与修改

用户反馈的下方 `2000/2000` 是累计模拟 tick（每步 50ms），约 100 秒模拟时间，不是 2000 份存档。但 v15 确实在每个模拟步通过观察回调克隆世界，再为所有居民生成感官、复制整帧并计算回放校验。即使只保留最近 600 帧，越来越大的记忆、地图和事件仍被重复放进每帧。逐帧重复更新人物、感官线和 HUD，以及高 DPI 下的 MSAA，也有额外 CPU/GPU 开销。

本次按用户新要求，在线游戏取消查看/保存回放、播放速度和下方时间轴；移除 controller 的 ReplayRecorder、ReplayPlayer 及 onSnapshot 回调，后台不再采集帧。旧本机回放数据不主动删除；离线回放内核和历史证据工具保留，但不进入在线主包。居民档案每两秒按版本保存，文字记忆、私人地图、阶段总结和任务继续可用。

LiveObserver 按 runId/revision/tick 收集档案，只在打开感官时计算当前选中居民的覆盖图，并只保留这一个结果。暂停期间复用同一场景，世界变化才更新角色和物件，选人或开关变化才更新感官；界面交互与档案详情显式触发刷新。档案 ID 集合复用，避免每步重建。

原子 checkpoint 保留一份完整世界和批次的来源/哈希/决定身份，不再同时保存 commit.nextWorld 和整批私人请求。写入完成仍是释放认知屏障的前置条件；写入失败继续冻结，重试同批次。没有改变模型上下文、决策、记忆、动作或模拟时钟。

默认「画面：流畅优先」关闭 MSAA、显示帧率 30；「精细优先」可恢复 MSAA/60，选择本机保存。保留高清画布，不使用模糊低分辨率缩放。两档都保持原本 20Hz 模拟，认知期间世界及步态仍冻结，网络/观察界面继续，不补跑等待时间。感官可视化默认关闭，底部可随时打开；不改变居民实际感知。移除时间轴后地图高度增加 40 设计像素。

## 实测

同一确定性四居民、本地算法、采集与建房场景；前后在 500、2000、4000 步的完整世界哈希一致，模型请求均为 0。

| 指标 | v15 回放路径 | 新在线路径 |
|---|---:|---:|
| 到第 2000 步测试总耗时 | 67,135ms | 6,959ms |
| 其中快照/感官/回放校验耗时 | 50,723ms | 0ms |
| 2000 步保留回放帧 | 600 | 0 |
| 到第 4000 步测试总耗时 | 205,961ms | 17,908ms |
| 4000 步保留回放帧 | 600 | 0 |
| 8000 步 | 未追加基线测试 | 51,376ms、0 回放帧 |

2000 步基线保留帧逐帧 JSON 大小合计约 362.39 Mi 个 UTF-16 code units（不是 UTF-8 字节，也不是手机实际常驻内存）；4000 步约 598.16 Mi。旧路径复制、分配和校验导致随运行时间上涨的负担。具体样本与单位见 performance-before-core.json / performance-after-core.json。总耗时包括证据采样及序列化检查，不是实时手机性能保证；storageMs 只测序列化，不测浏览器存储 I/O。

浏览器固定四居民、感官开启、暂停场景，连续调用 300 次 ObserverView.render：原先约 75.7ms，重复 300 次场景/感官更新、1200 次人物更新；新版本约 0.6ms，同一世界不再重复这三类更新。此项是 headless SwiftShader 的 JS 更新微测，不是 GPU 帧率；仍需真机评估发热和长时间体验。
