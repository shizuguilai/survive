# 档案分页与真实模型阶段总结

## 使用

打开居民「历史 / 档案」。默认显示实际行动和之前轮次，使用上一页、下一页翻阅；边界按钮置灰。点记录可读详情，详情页上下翻动长文，再返回列表。新记录到来只显示提示，当前列表保持稳定，点击「载入新记录」才更新。

切换「阶段总结」，右上可逐轮选择当前或历史轮次，再点击「生成真实模型总结」。已有总结可更新。系统最多选取120条该居民及公共公告记录，优先实际行动和计划，其余听觉、记忆补充；超出请求字节限制时缩小范围。界面显示输入条数和模拟时间范围，不能视为整轮所有事件都已归纳。

总结分为阶段总览、★关键进展、问题/阻碍、待执行计划、交流和后续关注。点关键点查看对应原始记录。只有行动凭据才能支撑“关键进展”，模型提示额外要求区分失败和成功，不把计划或听说当成已完成事实。引用和结构通过校验不等于语义绝对无误，原始依据仍保留供核对。

## 修复范围

旧列表每次历史版本变化都从最新记录倒序重算，持续新增会推移正在阅读的页面；默认仅本轮也会在重开后隐藏旧档。现在固定浏览快照、默认展示跨轮实际行动，并提供明确页码、上一/下一页、边界状态和独立刷新。按钮使用固定命中矩形，文本不截获点击。桌面与触摸窗口均验证。未直接观测到用户当时浏览器会话，不能断言这些是其唯一成因。

每个原始事件标识在恢复档案后仍唯一，供总结引用。原始流水不删除，保留全部流水和私人记忆筛选。档案仍为本机最近2000条；总结按居民/轮次保留最新一份，最多40份，并保存所引用输入，原始行滚出上限后仍可核对总结依据。

## 模型与模拟边界

`/api/summarize` 使用服务端既有智谱密钥，仅允许官方glm-4.5-air。真实总结是独立的观察者请求，不是居民的下一次决策，不会写入居民记忆或替居民选动作，也不会改变世界时钟。任何居民认知仍走原全局冻结屏障，完整批次提交才恢复，不补跑墙钟等待。回放只读取截止当前时刻的已存总结，不发起总结请求。

输入只含所选居民、单轮的已存条目及公告；不能混入另一个居民的私人记录。输出每个关键点引用1—5个现有记录标识；无效结构/引用仅尝试一次真实修复，失败显示错误，保留原记录和上一份总结，不用规则或Mock替代。页面等待时可继续翻阅。请求有时限、字节上限和独立并发限制。日志只记处理时长和错误类别，不记录总结正文/私人上下文。
