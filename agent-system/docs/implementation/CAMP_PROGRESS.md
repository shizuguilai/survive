# 营地目标与生存状态 v0.2

## 本次问题与修复
旧演示将长期目标固定为问候，缺少本人实际发声/行动结果的记忆；已完成动作仍进入currentPlan，导致模型重复问候或走到同一位置。现在保留本人已说出的片段、到达和失败事实，只传未完成动作，明确原计划已完成。仍由glm-4.5-air自行决定，不强制接任务、不用规则决定工作。

## 可用玩法
- 主场景为72×72地面、32处有限资源节点（木材/石料/浆果）、公告板兼仓储和池塘景观。摄像机支持拖动、滚轮和按钮缩放，原两树一墙保留为测试场景。
- 右上角“布置营地目标”：选资源、数量、补充说明；默认木材8份目标。公告须走近阅读，任务引用只能由本人读到；自主接受/拒绝。采集才增加任务进度，发声和口头承诺不会加进度。同类同时接受的任务依发布顺序计数，避免重复记账。
- 真实有限资源→个人采集袋（30份）→模型自主搬运到公告板旁公共仓储。浆果可由本人进食，每份降低16%饥饿。当前仓储支持存入，尚不支持领取或交易。
- 生命100；饥饿/疲劳按50ms模拟步更新。严重饥饿每模拟秒损失0.3生命；温饱且不疲劳时缓慢恢复生命；低于30生命移动减半，生命为0倒下且不执行动作；救援/复活未实现。休息降低疲劳。
- 任何居民思考，全世界的移动、采集、饥饿、疲劳和生命均冻结。此时发布的目标只进入观察者队列，提交后下一个模拟步才写入世界。

## 验证边界
本地真实模型45次独立请求，读公告/自愿接受/采集推进1份通过；不是8份整项目完成、线上浏览器、真实进食或长期协作验收。第一次真实尝试暴露重复到达并中止，保留失败记录。最后加入更具体的到达距离、失败事实和生命倒地显示后做类型/单元/构建/浏览器回归，不重复声称这些文案微调已有独立长期实测。
浏览器：桌面与窄屏模拟下原生Laya任务面板、目标队列、资源节点和生命/饥饿/疲劳显示；不是真机。所有真实证据只发布脱敏计数，未发布居民上下文或截图。
