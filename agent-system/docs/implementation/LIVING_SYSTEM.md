# 生活系统：需求、昼夜和住房成长

2026-09-28；继续使用 LayaAir 3.3.12、TypeScript 和原有三种运行模式。

## 操作变化

- 规划接收提示最多显示4.5秒，任务实际入板后立即清除。暂停时也能自动消失；尚未入板的数量保留在小型任务状态中。
- 顶部统筹简介保证两行完整显示，点文字展开完整信息；全文可滑动。
- 背包、生活详情和完整统筹信息支持单指上下滑动、滚轮、拖动右侧滑块。去掉背包的上/下翻页按钮。
- 生命、饱腹感、心情和精力统一为越高越好。内部 hunger/fatigue 的旧含义不变，展示用1减去原值，避免破坏既有记录和动作协议。
- 人物上方的「心愿」是给观察者看的自身需求，和带引号的实际发言分开。它不进入声音队列，也不会被另一居民听到。
- 居民卡的「生活详情」展示心情原因、住宅面积、家具、整洁度、柜内物资、扩建愿望和罢工倒计时。当前活动仍显示实际动作。

## 模拟规则

| 系统 | 当前规则 |
|---|---|
| 昼夜 | 7200 tick为一个模拟日（6分钟），从08:00开始；20:00—06:00为夜间，黄昏/黎明渐变 |
| 精力 | 工作和行走消耗，休息恢复；本地执行器在精力不足或夜间疲惫时优先休息 |
| 床 | 4木材；真实进屋后可躺床休息，比地板、野外恢复快 |
| 柜子 | 3木材1石料；24份个人资源容量，haul/withdraw实际存取，仅屋主可使用；家具损坏不删除内部物资 |
| 灯 | 2木材2石料；夜间灯和暖色光区显示，缓解缺少照明的心情损失 |
| 拖把 | 1木材；房间会逐渐变脏，home_care/clean用4模拟秒打扫，恢复整洁度 |
| 心情 | 温饱、精力、疼痛、露宿等待、缺床、黑暗、整洁和扩建等待共同影响；不使用墙钟 |
| 失控 | 心情归零后罢工30模拟秒；若人在自己家中且有家具，部分情况会损坏一件自家家具。随后冷静并恢复最低心情，半日冷却，避免连续触发 |

家具不是生成时送出的装饰：角色必须到自己的屋内，花时间并实际扣除公共仓储材料。缺料和竞争会失败并给本人反馈，再重新备料。柜内物品和公共仓储分开，状态栏只统计真正公共入库物资。

## 住房成长

目前为三个体量：4×3 → 5.5×4.5 → 7×6。每次完工居住满一个模拟日后，可能希望提升一级。扩建使用 home_care/expand，执行前必须满足个人已知居住区空地和全部材料要求（每级12×等级木材、8×等级石料）。

成功发起时材料从公共仓储预留到个人工程，防止拆房后被其他人抢完材料。随后真实执行「拆旧回收 → 地基 → 墙体 → 屋顶」；拆旧回收旧屋50%的木石，家具和柜内资源保留。空地或材料不足时旧房不动。能原地改建就原地改建，否则在本人知道的居住区内寻找合适新位置。已预留的地块也参与占地检查，避免多人选到同一位置。

网格、碰撞、地板、门口和路线一起使用新尺寸；屋顶开关继续可用。一片居住区持续容纳多个家庭。尚未实现任意建筑蓝图、拆除居住区、拖拽改变旧区域或无限层级住宅。

## 模式与隐私

- 本地模式按基本生活需求和已知目标执行，明确标记 LOCAL_ALGORITHM；统筹模式向glm-4.5-air提供居民的生活报告和改善住处选项，阶段执行器照顾吃饭与休息。独立模式由模型选择home_care等动作。
- 新动作有闭合输入协议、个人引用检查、距离/所有权/资源前置校验。新增字段进入自身身体报告，不给其他居民提供私人心愿。
- 日夜、等待、罢工、清洁、精力、施工和手部/睡姿动画均取模拟tick；模型思考、暂停、提交时全世界冻结，继续后不补跑。
- 扩建、家具和失控不改写另外一个人的私人记忆。实际说话仍由speak逐片段产生。

## 验证和边界

自动测试覆盖通知消失、单指滚动与滑块、日夜、家具材料、个人柜子隔离、心情后果、躺床恢复、保留物资的拆旧重建和大屋门口路径；原有认知屏障、隐私及墙体测试一起运行。结果见 `evidence/living-unit-tests.txt`。

`node tools/verify-living.ts` 从原始地图、零公共库存、两名居民开始，真实推进本地模拟，要求两人各自完成建房、四种家具及二级改建，禁止远程调用。实际tick、竞争失败和行为记录见 `evidence/living-local.json`。这是本地算法验收，不代表远程模型会选择完全相同的生活安排。

本轮未进行实际浏览器渲染、手机触屏或微信真机验收。当前受管预览要求的浏览器控制技能不可用，且该静态Laya/Worker工程没有兼容预览服务；没有用旁路浏览器替代。
