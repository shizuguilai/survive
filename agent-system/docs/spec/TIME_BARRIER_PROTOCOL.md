# 全局认知屏障与模拟时间协议

这是本包的核心协议。最新用户决定：**一旦需要模型思考，全世界停止推进，计算时间对所有居民不可见。**

## 1. 三种时钟

| 时钟 | 使用者 | 思考期间 |
|---|---|---|
| `SimulationClock` | 世界、身体、行动、声音、感知、记忆时间、心跳、租约 | 完全不前进 |
| `RuntimeClock` | HTTP、连接超时、重试、真实耗时统计、运维、只读存盘 | 正常前进；不能进入角色上下文 |
| `PlaybackClock` | 观察者回放进度、显示插值、播放控件 | 独立；只播放已提交模拟记录 |

`SimulationClock` 以整数 tick 计数，`fixedDtMs = 50`。时间换算必须有明确单位。世界日历是 tick 的映射，不读当前电脑时间。生产、饥饿、施法、说话不能使用 `Date.now()`、`setTimeout`、动画完成真实计时等作为结算依据。

运行时间为真、模拟时间不动，不是矛盾。离散事件模拟中，模拟环境可独立管理自身时间与事件推进；这里仅借鉴这种原则，保持 TypeScript 实现，不引入 SimPy 依赖。[S7]

## 2. 暂停矩阵

必须冻结：所有实体位置与运动状态、NPC 动画采样时间、非 UI 粒子、刚体、血量/饥饿/疲劳/年龄、工作进度、天气/昼夜、声音发射与传播、台词播放进度、任务期限、私人记忆衰减、认知心跳、游戏内计时器、NPC 摄像机与感知采样。

必须继续：网络请求与响应处理、真实时间超时/退避、取消、诊断状态、观察者摄像机、选人、感官开关、加载提示、只读存盘、后台用户鉴权。

世界修改：暂停期间只能排队；不能改变正在供模型思考的快照。暂停 UI 的草稿不算世界修改。模型输出先写 staging，未完成批次的结果不能影响其他模型输入。

认知提交本身可以更新意图、允许的私人记忆和命令队列，但不推进身体。这里区分“世界物理状态不随计算时间变化”与“认知事务提交时改变意图”；不要把整个对象 hash 永不变与提交更新混为一谈。

## 3. 状态机

```text
RUNNING
  └─ 完整模拟步结束，dueSet 非空 → COLLECTING → THINKING
THINKING
  ├─ 所有必要回复有效 → VALIDATING → COMMITTING → READY
  ├─ 超时/无权限/结构错误重试耗尽 → ERROR_PAUSED
  └─ 用户停止本次运行 → STOPPED
READY
  ├─ 有 USER_PAUSE / APP_BACKGROUND 等其他暂停原因 → 保持暂停
  └─ 无其他暂停原因 → RUNNING（重设真实帧基准，不追帧）
ERROR_PAUSED
  ├─ 用户修复配置/重试 → THINKING（同一冻结快照）
  └─ 用户中止 → STOPPED（保留快照与原因）
```

暂停原因采用 token/ref-count 集合，例如 `COGNITION:<id>`、`USER_PAUSE`、`APP_BACKGROUND`、`ERROR:<id>`。完成一个 API 请求不能清空用户手动暂停。`speed=0` 不能代替全套暂停状态。

## 4. 安全步边界

第一版不尝试在一个物理计算循环的中间任意中断。按如下顺序处理一次正时间步：

1. 确认没有屏障和其他暂停 token；开始一个完整 tick。
2. 应用此前在安全边界登记、此 tick 到期的玩家世界命令。
3. 验证动作前提，执行既有意图的一小步，推进身体、资源、声音与环境。
4. tick 加一；按确定顺序结算该时刻的世界事件。
5. 感官采样、私人收件箱更新、注意力/心跳产生 dueSet。
6. dueSet 非空则同步获取屏障 token，再启动异步请求；本帧即使仍有 dt 余额，也不得再进入下一模拟步。

启动状态 `tick=0` 可直接对所有居民做 bootstrap 认知屏障。此时尚未行动，但每人初始常识、背景和亲历起点必须显式定义。

检测分辨率最多受一步长及感官扫描周期影响。声音开始/身体疼痛等事件直接进事件管线，不必须等较慢的视觉扫描。

## 5. 每轮请求与提交

屏障记录包含 `runId / barrierId / tick / worldRevision / snapshotHash / dueAgentIds / causeObservationIds / status`。

冻结 snapshot 后，对 dueSet 每人各自构造 `CharacterContext`。可并行请求，但必须做到：

- 每人只看自己的感官、记忆和知识；同批次中不会看到别人尚未执行的台词/决定。
- 传输 metadata 内的 barrierId 等不拼入角色消息。HTTP/服务端日志不得倒灌角色上下文。
- 回复到达时只写对应临时槽位，并核对 run/barrier/agent/request generation，拒绝过期与重复。
- 等全部必需回复获得有效完整决策，再统一校验、裁决共享资源并生成 commit。
- 一次原子提交所有已接受意图、私人记忆改动、下次心跳与动作队列。持久化提交后才解除屏障。

部分成功、部分失败时不能先让成功的角色走起来。成功回复可以保留，失败的对应角色重新请求；没有新模拟事实时不必重新推理其他人。修改快照或运行分支则必须整体作废旧批次。

同一主体严格一条可提交认知事务。模型内部可多次合法查询自己的记忆，期间仍处于同一屏障；不能借“工具调用”移动身体、免费转头或即时查看墙后。

## 6. 同时决策冲突与零时间限制

两个居民同时要求拿同一把斧头：API 先返回者没有优先权。规则裁判按已记录的预留与确定的公平顺序提交竞争结果。失败结果排入后续正时间步的行动反馈，不在同一 timestamp 无限触发重新选择。

外界动作（发声、走动、阅读、新物资产生）必须在 `commitTick+1` 或之后生效，持续时间至少一个 tick。JSON 修复属于当前事务内重试，不是一个新世界事件。

私人思考不产生可被别人听到的“决定事件”。同一观察事件每名居民只消费一次；相同状态重复提交继续执行，不得立即唤醒自己。

对话事件、合作请求不能在零模拟时间里形成无限 A→B→A 循环。工具与格式修复设置有界次数；异常循环进入 `ERROR_PAUSED`，不能为打破循环偷偷推进世界或伪造决定。

## 7. 两人打招呼：规范时间线

以下是人为设定的测试样例，不要求真实模型每次都选择礼貌回应。

| 模拟时刻 | 世界事实与处理 | 可经历的时间 |
|---|---|---|
| 5.00s | A、B 进入各自可识别视野；形成两个观察 | 两人已经看见对方 |
| 5.00s 屏障 C1 | 两个独立模型决定；真实等待可能 20s | 世界仍是 5.00s，没有尴尬等待 |
| 5.00s 提交 | A 选择停步并说“早上好”；B 选择注视 | 意图生效，声音尚未凭空完成 |
| 5.05s 起 | A 的发声动作运行，声音逐段传播 | 正常说话时长 |
| 5.80s | B 实际获得足够清晰的“早上好” | 此时才能基于这句内容回应 |
| 5.80s 屏障 C2 | B 的模型选择回应；全世界暂停 | A 的动作、其他人的工作都不多走一秒 |
| 5.80s 提交后 | B 下一步开始发声 | 回应具有自己的时长 |

若双方都选择同时说话，形成声学重叠，可能互相没听清。系统不能人为让某人提前知道另一人的话。若模型选择先停步等待，等待上限是模拟时间；计算暂停不会让它超时。

默认语音分句/片段传递。整句字幕不能在第一个声音波前到达时全部提供给听者。尚未发出的后半句不得进入对方上下文。

## 8. 推荐步进伪代码（结构示意，不是已实现代码）

```ts
function onObserverFrame(nowWallMs: number): void {
  observerUi.update(nowWallMs);  // 无权改世界事实
  renderer.render(lastCommittedSnapshot, observerCamera);

  if (pauseSet.size > 0) {
    lastWallMs = nowWallMs;
    frameAccumulatorMs = 0;
    return;
  }

  const delta = clampFrameDelta(nowWallMs - lastWallMs);
  lastWallMs = nowWallMs;
  frameAccumulatorMs += delta * requestedSpeed;

  while (frameAccumulatorMs >= fixedDtMs && pauseSet.size === 0) {
    frameAccumulatorMs -= fixedDtMs;
    const result = worldStepper.stepOneTick(); // 同步、固定顺序、无网络
    if (result.dueAgentIds.length > 0) {
      const token = pauseSet.acquireCognition(); // 必须先拿 token
      frameAccumulatorMs = 0;
      void coordinator.resolveAtFrozenBoundary(result, token)
        .catch(error => enterErrorPaused(error));
      break;
    }
  }
}
```

`resolveAtFrozenBoundary` 的出错分支不可无条件 `finally resume`。只在提交成功且相应 token 合法时释放认知暂停；异常添加错误 token。恢复时也重设 wall 基准。并发回调只能提交一次。

## 9. LayaAir 适配要求

不能仅设置 `Laya.timer.scale = 0` 就声称所有冻结已完成。官方文档介绍了 timer 与暂停能力[S8]，但本项目要单独核对并控制：场景脚本更新、物理自动步进、Animator、Tween、粒子、Shader time、声音播放、网页媒体元素、客户端 UI 时间源。

首版推荐让权威模拟与角色运动来自纯 TS，3D 表现按模拟进度采样；不让引擎自动物理在另一时间轴偷偷移动人物。确需自动物理时，实现 `EngineWorldPauseAdapter` 并写跨真实等待的状态测试，验证其与指定 Laya 版本兼容。

暂停期间模型发声不是在真实音轨里偷偷播完。台词音频/字幕进度以模拟播放位置重建或暂停恢复；播放光标与可听内容一致。引擎不支持可靠 seek 时，首版使用定长文本/声音事件，不伪装完成语音支持。

UI 摄像机可以移动，但居民头部不能被玩家摄像机带动。场景冻结的 shader/动画与 UI 加载旋转动画分开。

## 10. 玩家修改与暂停嵌套

屏障期间划区只改草稿；确认后加入有序命令队列。该命令在屏障完成后的下一正时间步应用，并作为世界内公告/标记被感知。既有动作执行前验证前提，发现冲突返回合法感知反馈；不能给模型泄漏幕后改动理由。

用户在思考期间按暂停，认知可完成并提交，但世界仍保留 USER_PAUSE。按继续只解除 USER_PAUSE；未完成认知或错误暂停仍不能推进。

App 切后台也是独立 token；回来不补跑真实离线时间。v1 不做离线资源追算。

## 11. 超时、取消、重启与持久化

网络超时与重试使用 RuntimeClock，例如 120 秒超时、2 次自动重试是可调初值，不是模型性能承诺。重试期间世界仍暂停。失败后显示明确原因；用户可重试、修复配置或中止。

没有 key / 返回非法动作 / 无权限 / 内容不可解析时，不能降级成规则角色继续运行。Mock 只能在显式测试模式和有标识的回放中使用。导出记录必须标出每次决策来源。

每次请求使用幂等 requestId；服务端、客户端、提交器三级拒绝重复。重启后只恢复最后完整 commit 与其后冻结 pending 状态。已经完成但未持久化完整事务的部分回复，不作为已执行行为。日志采用 prepare/commit 标记和快照校验，避免读档重复发声或重复扣资源。

## 12. 回放和真实等待的关系

离线预计算可以任意等待模型，输出逻辑 tick 顺序的完整运行记录。回放按模拟时间读取位置/行动/声音/感官记录，不播放网络等待的墙钟空档。

现场观看必然可能看到世界冻结；只读摄像机与 UI 仍流畅。不能宣传“现场完全无停顿”。有限预缓冲在生产速度低于播放速度时会耗尽；耗尽必须显示缓冲并暂停播放，不能补造未模拟的后续。

重要：裁掉 API 等待不等于裁掉人物主动犹豫、说话、走路的时间。这些是已经进入模拟世界的行为，回放必须保留。

## 13. 屏障必须满足的性质

- Freeze：WAITING 期间且提交前，物理世界 hash、tick、声音光标、行动进度、任务期限不变。
- Atomicity：没有半个认知批次先行影响下一次观察。
- Latency independence：在相同输入命令、种子和已接受模型决策固定的前提下，改变 API 延迟不改变模拟轨迹。
- Arrival-order independence：固定回复集合下，改变响应到达顺序不改变资源竞争与提交结果。
- No catch-up：恢复第一帧最多按正常新 dt 推进，不补模拟网络等待。
- No knowledge leak：角色请求不包含 RuntimeClock/后端异常/屏障等待。
- Liveness boundary：模型成功才能放行；模型永久失败则可恢复地暂停，不以假决定换取活性。

这些是待通过的工程测试，不声称真实模型重问必然返回相同文字或行为。
