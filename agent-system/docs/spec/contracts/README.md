# 契约使用说明

这里是JSON Schema 2020-12的规范草案，已经做结构与样例自检，但没有代表游戏逻辑已实现。供应商不支持完整JSON Schema时，网关仍必须本地验证，不能丢掉语义权限检查。

## 动作阶段

`actions[].stage`表示同一计划的阶段编号。同阶段动作可并行，仍必须通过身体通道检查；后续阶段要等前一阶段完成。例如问候样例在stage=0同时停止行走和说话，不代表先等完再说。`continue`只能保留当前计划，不与重新定义该计划的动作混用。阶段引用、可达性、身体通道和循环需语义检查，不能靠schema自动证明。

至少一个正模拟tick后才能开始新动作。`nextReviewAfterSimMs`是下一次计划审视，不是行动必须持续这么久；新感官事件可更早唤醒。

## 观察与输出权限

观察schema是发给该角色的内容，不允许世界实体ID、敌意标签、隐藏坐标、未听清原文等字段。匿名观察引用由每名居民的本地可见事件序列生成，不能由全局隐藏事件编号或秘密属性推导。

`recognizedName`、`knownRef`即使结构合法，也必须由程序检查本人有识别依据。模型猜一个引用不能提升权限。

亲历观察由工程按感官写入；模型只能建议带证据的belief/summary，不能任意新增“我亲眼看见”的事实。语义幻觉仍需评测，不能用schema通过代替。

## 回放

manifest仅供引擎/观察者。`endTick>=startTick`、文件存在、日志hash和real/mock计数等要运行时额外验证。所有文件路径按包内白名单解析，禁止目录穿越。

## 提交封装

角色决策外再封装`runId/barrierId/agentId/requestId/tick/worldRevision/contextHash`等编排数据。封装不发送为角色经历，日志也不能被角色工具读取。
