# Survive：规划者与自治居民 — 系统设计

版本 1.0.0。所有“必须”是实施约束，所有默认数字是原型起点，不是人类认知研究结论或真机性能结果。

## 1. 游戏是什么

玩家通过土地用途、发展目标、物资边界影响营地。居民各自观察、记忆、思考、提议、协作和执行；世界不是由玩家逐项派工，也不是由一个全知 AI 控制。

核心体验：看见有性格的人因为自己的经历形成决定；合作推动营地发展；失误有能追溯的原因；玩家通过改变规划而不是代替每个人操作来解决问题。

首版以小规模原生 3D 俯视营地为目标。Web 是优先验证载体，手机触控必须可用。横竖屏采取响应式布局；不把其他推币项目的 9:16、包名、发布配置、模型凭据带入本项目。微信/抖音正式发布、多人联机不是本包已验证能力；如列入后续范围，单独验收。

## 2. 不能混淆的四个边界

| 边界 | 允许 | 禁止 |
|---|---|---|
| 世界事实与个人认知 | 感官按条件生成个人观察 | 给模型全部 world state 再要求装不知道 |
| 思考与执行 | 模型发计划；程序执行路径、计时、碰撞 | 工程自动挑最优职业或代替人答应合作 |
| 计算耗时与世界时间 | 认知期间冻结模拟，网络继续 | 等待后追帧补上过去的真实时间 |
| 观察者与角色 | 玩家看调试覆盖层、日志 | 玩家镜头、隐藏实体 ID、真实 API 延迟进入角色上下文 |

“每个居民接入大模型”定义：每人独立产生自己的决策，使用独立私人上下文和模型请求；可以共用同一服务商、模型、连接池和服务端进程。批量 HTTP 只是一种传输，不得将一段全知联合上下文冒充多个独立人物。

## 3. 总体架构

```text
观察者/玩家界面（LayaAir 原生 UI 与 3D）
  ├─ 摄像机、划区草稿、感官覆盖层、播放控件、后台状态
  └─ 世界修改请求 → 有序命令队列 → 安全边界提交

纯 TypeScript 模拟核心（唯一世界事实来源）
  ├─ SimulationClock + WorldStepper + SeededRandom
  ├─ 地形/身体/动作/资源/建筑/声音/公共载体
  ├─ Perception → Attention → 每人的私有观察收件箱
  ├─ GlobalCognitionBarrier → Snapshot → PendingBrainBatch
  └─ 决策校验 → 同步原子提交 → 新意图交给 ActionExecutor

私有认知上下文构造器
  └─ 个人身份 + 自己的经历/记忆 + 有证据的观察 + 原计划
       → 服务端模型网关 → 独立模型回复 → 结构与能力校验

记录与回放
  ├─ 权威快照、已提交命令、感知记录、已接受决策、随机流
  └─ 回放时钟 → 同一份只读表现，不再推理、不再接收世界修改
```

禁止 `World.tick()`、感官、动作执行器直接 `await` HTTP。屏障在步进器外部管理；事件循环能继续处理 Promise、计时器和观察 UI。纯模拟层不导入 `cc` 或 `Laya`。引擎适配层才处理 3D 节点、相机、网格和输入。

## 4. 时间机制：最终确定版

只要一个居民需要认知，当前完整逻辑步结束后、下一步开始前，建立全局屏障。暂停所有居民运动、身体状态变化、攻击、施工、种植、声音传播、说话进度、天气、任务租约和认知心跳。允许后台模型请求、校验、存盘和观察者 UI 继续。

同一边界需要思考的人并行请求，各看同一权威快照经过自身感官过滤后的结果。未被唤醒的人不必附带思考，但其身体同样冻结。回复先存临时区；全部成功后统一提交。失败则保持故障暂停，不放行一部分人。

当认知完成，角色的意图/记忆可在同一模拟 tick 的提交阶段更新；位置、年龄、饥饿和行动进度不得因为计算耗时变化。已计划的说话、行动至少到后续正时间步才产生可感知效果。

三种时间及所有异常由 `TIME_BARRIER_PROTOCOL.md` 规定。不要用“API 很快”作为不实现屏障的理由。

## 5. 居民数据

每名居民至少包含以下持久状态：

- 身体：位置/朝向、眼睛与头部方向、生命、疲劳、饥饿、受伤、持物、背包、动作执行状态。
- 个体：世界内姓名、背景、性格倾向、能力、熟练度、偏好、关系；不使用固定职业控制可选工作。
- 认知：当前目标、计划版本、正在执行的动作、关注条件、下次模拟时间审视点、已承诺的合作。
- 经历：自己的观察、行动反馈、转述、判断、摘要，带来源和模拟时间。
- 知识：已探索地图、最后已知位置、已读公告、自己知道的可执行技能。

技能影响行动效率或能否做，不替代“是否愿意做”的模型判断。关系、性格变化由模型提出有依据的更新，程序校验目标与范围；不能由模型任意修改别人性格或凭空改库存。

有限感知不等于无限短视。居民可以推断墙后发生了什么，也可以误判；推断必须标为个人信念，而不是被写回世界事实。

## 6. 下意识执行器

执行器支持模型事先批准的参数化技能：步行、观察、倾听、采集、搬运、施工、进食、休息、说话、阅读、写公告、请求合作、参加项目。

例如模型批准：采集已知树木以获得 12 单位木材；背包满后按已知路线送到已知仓库；遇到未知障碍则停止本段动作并触发认知。执行器不能自行选择隐藏树林，也不能因为模型失败而另找一份工作。

必须区分：

1. 物理必然：碰撞不能穿墙，失去生命不能继续行动，树木被砍完不能继续产物。
2. 技能内部流程：按批准的路径移动、累计采集进度、转身、抓取已选物体。
3. 自主决定：换目标、是否帮助别人、是否放弃承诺、是否接受风险。交给该居民模型。

立即身体刺激在该步结算后触发屏障；不要求恢复尚未发生的物理步骤。步长决定发现事件的时间分辨率。首版采用 50ms 模拟步长；不是每 50ms 请求一次模型。

动作占用身体通道：双手工作与双手施工不可并行；行走可以伴随说话；仔细倾听可请求暂停敲击声来源；一个嘴巴同时只能执行一个发声动作。占用规则是技能约束，不是替人物选人生。

## 7. 频率与注意力

有三类唤醒：感官显著变化、原计划/动作完成或失败、模型预约的模拟时间检查。启动时每名居民必须有一次真实认知。稳定工作也按心跳再次由模型决定是否继续，不能永久退化成脚本。

默认审视间隔 3 模拟秒；模型可在 1—10 秒范围调整。注意力按新奇、强度、变化和已设关注条件过滤，不推断隐藏敌我身份。工程判定“进入视野的陌生轮廓”不是“危险敌人”。

同一持续刺激采用进入/变化/离开事件及迟滞，禁止每帧重复唤醒。思考暂停时模拟时钟不动，因此不会由于真实等待产生新的饥饿、心跳或感知事件。

## 8. 土地与玩家行为

首版主区域：居住、种植、作业/仓储。覆盖规则：禁止进入、禁止建造、允许采集、预留通道。区域不是立刻铺满建筑的命令。

每区包含用途、已提交边界、容量目标、发展优先级、材料预算/额度、建设标准、已存在建筑处理策略。玩家划区先是 UI 草稿，确认后成为世界命令。认知屏障期间只排队，不修改冻结的快照。

区域变更生成世界内可见边界和可阅读公告，不广播进入所有人的脑海。NPC 只能基于读过/听说过的规则主动遵守；碰到未获知的硬性边界时，返回可感知的施工/通行反馈，不附带幕后真相。

重划不自动拆除居民住宅。既有建筑与新用途冲突先标为过渡对象；拆迁是独立的规划指令和居民项目，不瞬间抹掉人和物资。

玩家只设置长远目标，不能通过隐藏操作给某居民强行修改想法。任何后续“直接指派”功能必须作为新的产品决定，不混入当前自治模式。

## 9. 建设与合作：不是全知任务派工器

世界可以维护资源与项目事实，但居民访问必须有对应渠道。公告板有真实位置；读取要完成走近、观看/阅读动作。后台 `ProjectLedger` 是共享资源一致性账本，不是可被任意脑请求读取的全局任务板。

项目生命周期：个人发现需求 → 形成提案 → 通过谈话/公告招募 → 居民独立接受或拒绝 → 规则验证预算/地块 → 资源预留 → 依赖任务执行 → 成果被观察 → 评价与记忆。

施工任务可以拆为清理、采集、搬运、建造；顺序由已有工艺约束，居民自主决定参加哪部分。房屋选址工具只基于居民已知地图给出候选，不借助全图寻路泄漏隐藏墙体。真实碰撞/占地最终由权威世界验证。

不可在同一次认知批次里让 B “听见”A 尚未真正说出的合作提议。临时项目协调者也必须是有人通过世界内交互接受的责任，不由服务端隐形选举产生。

材料争抢由明确、可重放的规则处理。建议按提交 tick、项目已有预留、循环公平顺序裁决，不按 API 回复快慢、不永久按居民 ID 小者优先。落败者只收到实际可感知的“材料已被占用/未能取到”等反馈，再触发个人决定。

## 10. 对话是物理行为

两个人相遇 → 实际互相看见 → 触发一次批量认知屏障 → 独立决定是否打招呼/停步 → 提交行动 → 正常模拟发声 → 听者获得可懂片段 → 新屏障 → 回应。

API 耗时是零模拟时长；说话、走近、抬头和主动等待有正模拟时长。不可让两人依靠零时间的模型内部消息来回聊完十轮。听觉对部分遮挡/噪声产生不同结果；对话双方和旁听者只有自己的接收文本。

角色有权不打招呼或不回应。工程验收不能把“总会热情回应”写死；真实模型验收检查其决策是否被真实执行、未接收到的信息是否泄漏。

## 11. 可视化、记录与回放

观察界面可以切换：全部覆盖关闭、选中居民、开发者全体概览。视觉是跟随头部方向的扇形/截锥地面投影，包含被遮挡部分；听力是以参考声音标定的环形覆盖和实际声音波纹，不冒充无论音量都恒定的听觉边界。

记录的感官数据是绘图唯一来源；绘图不能再调用一次独立感知并产生第二份事实。屏障期间可旋转玩家镜头和切换覆盖层；居民视线、脚步与声音进度保持冻结。

现场模拟让玩家明确看到“世界暂停，居民思考中”，允许操作观察界面。不能保证现场没有可见停顿。先计算后回放则按模拟 tick 播放已确认内容，裁掉计算等待。回放无需模型服务，可暂停、倍速、选人、切感官；不支持同时改过去的世界。后续分支实验必须显式复制存档并创建新 run，不静默篡改原记录。

## 12. 引擎、存档与迁移

本次基线的 `core` 已与大部分渲染分离，但工作分配按 `JobType`，需重构；`GameRoot.update` 使用真实帧 dt 累积步进，不能简单插入网络 await。参见来源 S1—S6。

建议新增 `packages/sim-core`、`packages/contracts`、`apps/laya-client`、`services/brain-gateway`；旧 `assets/scripts` 不先删除。运行时不同时加载 Cocos 和 Laya 渲染。小地图起步，角色运动由纯 TS 数学/网格实现，Laya 负责 3D 外观和查询适配；避免引擎自动刚体成为另一套独立时间源。

老存档转换保留物资、建筑、已有人口和位置；旧职业只可转换为经历/技能背景，不再决定固定工作。新性格生成必须记录来源与种子/模型记录。保存转换前原始文件，不覆盖旧格式。

新存档保存 schema 版本、模拟时钟、随机状态、身体/行动、私人知识与记忆、项目预留、事件队列、已提交决策、最后完整屏障提交。API key 不入存档或回放。恢复未完成屏障时回到冻结快照，不将未完整批次当作已执行。

## 13. 首版完成标准

两个居民能通过有限感知发生真实模型驱动的相遇与回应；观察者能看见扇形视野和听觉参考环；30 秒真实 API 等待不会导致世界前进；失败保持暂停；相同已接受决策的重放结果不受 API 延迟和返回顺序影响。

随后扩展到 8—12 名居民、三个区域、一个住宅建设和粮食项目。数量是首版范围，不是性能上限。旧尸潮/战斗单独开关，默认不在第一条闭环里运行，不以它掩盖认知和合作错误。

最终验收执行 `ACCEPTANCE_TESTS.md`，并区分 Mock、真实模型、浏览器、构建与真机结果。文档本身不构成这些结果。
