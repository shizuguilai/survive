# 有限感官、注意力、私人记忆与可视化

本文件定义角色与世界之间唯一合法的信息入口。数字与公式都是可配置的游戏模型，未经生理或声学拟真验证；禁止对外宣称还原真人感官。

## 1. 信息管线与权限

```text
WorldTruth（引擎/模拟器私有）
  → SensorEvaluator（角色位置、方向、能力、环境）
  → PrivatePercept（此人实际能感受到的内容）
  → Attention / 私人收件箱
  → MemoryRetriever + ContextBuilder
  → 该居民模型
```

v1用工程生成的受限语义观察作为模型输入，不要求每轮上传角色摄像机截图。未来增加图像感知时，也只能使用角色自身可见内容，排除观察者UI和覆盖层。

`WorldTruth`、`DebugTruth` 不得作为 `CharacterContext` 的字段。先创建专用白名单 DTO，再序列化，禁止 `JSON.stringify(world)` 后过滤部分字段。角色对象引用只使用每人私有的 `obsRef / knownRef`，通过带权限的能力映射解析；不要暴露能反查真名、阵营或实时坐标的全局实体 ID。

同一对象被 A/B 看见可以有不同的匿名引用与识别程度。内部仍可用真实实体 ID 做追踪，但不进入模型输入、函数名、文件名、工具返回、报错详情或记忆检索结果。

## 2. 视觉

### 2.1 采样流程

1. 从模拟的眼睛位置和头部朝向建立视域，不能使用观察者摄像机。
2. 空间索引粗筛距离，计算水平/垂直夹角，排除视域外对象。
3. 对对象的代表点做遮挡检查；首版可使用头/躯干/脚多个采样点，避免单点刚好露出就泄漏全身信息。
4. 依据距离、可见比例、照明/对比、视力参数生成“检测 / 外观辨认 / 身份确认”级别。
5. 与该居民已有感知轨迹比较，输出进入、显著变化、丢失视野等事件。
6. 可见属性经过字段白名单。生命值、阵营、敌意、未来意图、背包隐藏物品不属于视觉字段。

距离和角度检查在同一权威模拟快照执行。首版视觉 200ms 模拟间隔；转头动作结束可立即安排一次采样。场景灯光的美术亮度与逻辑照明参数需绑定，不让后处理曝光改变居民视力。

### 2.2 可识别程度

- detected：“左前方似乎有移动的轮廓。”
- described：“一个穿深色外套的人，手中有长条状物。”
- recognized：“你认出了阿禾，他举着一根木棍。”

`recognized` 必须有合法个人记忆或先前身份来源。即便识别其姓名，也不能附上真实敌意、精确血量或对方内心。

身份误识别可作为后期扩展；v1 优先允许“不确定”而不是随意捏造姓名。程序错误不能伪装成角色误判。

### 2.3 离开视野

从实时轨迹切换为 `lastKnown`：保留最后观察的模拟时间、位置精度和来源。不能继续读取隐藏实体的位置。通过遮挡后再出现，按新的感知重新绑定；在未认出身份前保留匿名轮廓。

地图信息也属于个人知识。寻路规划依照个人已知地图；未知地形可作为探索区域，不调用全图最短路泄漏未知墙或敌人。实际执行遇到碰撞才形成新事实。初始共同地图必须是显式背景资料，不能默认全地图透明。

## 3. 听觉

### 3.1 声音是世界事件

每个发声事件有内部声源、开始 tick、持续 ticks、音量/类别、已发出的台词片段和传播参数。声音传播、台词进度都只由 SimulationClock 推进。

首版可以采用相对可听度：

`audibility = sourceLevel / (1 + (distance/referenceDistance)^2) × transmission × masking`

全部量采用设计规定的相对单位；不是分贝或严谨声压模型。`transmission` 表示门、墙等损失，`masking` 表示环境噪声影响。材质表、阈值和公式版本必须进入配置和回放版本。

声音经过墙体不必完全消失；使用近似透射。首版不要求回声、衍射与完整声场。官方声学与引擎资料只能作为实现参考，不等于本项目已有物理拟真结果。[S10]

### 3.2 三种不同结果

- 检测到声音：类别/粗方向/近中远，不一定能听懂。
- 理解语句：只提供当前已发出、已传播、足够清晰的片段。
- 识别声音来源：基于已知声纹/过往经历；并非后台知道是谁就自动识别。

隔墙听到“快……帮……”不能在任何字段里附带原文“阿林快来仓库帮我”。缺失片段直接删去或明确标注“没听清”，不能把原文放在注释、引用或 tool metadata 里。

精确声源坐标不发送。默认方向量化为八方，距离为近/中/远；随能力与可听度可改变精度。声音被听见，不代表原因已知；“木材掉落的声音”不能自动变成“某人故意推倒木材”。

### 3.3 说话和听到的先后

文本被模型生成不是声音已经发生。`speak` 意图在下一模拟步开始执行，按设定语速产生正时长声音。每个已发出片段才有资格传播；不同听者接收到的内容分别计算。

首版可用分句/短片段事件，不要求真实语音识别。若使用 TTS，合成请求也不得推进模拟，音轨时长和片段对齐要提前确定；不得拿真实播放器结束回调直接推进游戏时间。

发声途中角色离开听力范围，后半句不再自动获得。两人同时说话要按噪声规则处理，不给双方秘密保送完整文本。

## 4. 身体、触碰与内部信号

由工程生成疼痛、受力、撞击、动作受阻、饥饿、疲劳、身体失衡等感受；不附加不可观察的施害者和动机。可感知的身体状态用“轻微 / 明显 / 严重”等区间，真实血量保留在世界内部。

持续饥饿按阈值跨越/显著变化触发，不每 tick 重新推理。痛感首次出现可立即触发认知屏障。屏障期间这些值与衰减不前进。

嗅觉、温度、触感精细化留接口，首版至少视觉、听觉、触碰/疼痛、饥饿/疲劳四类。不要把尚未实现的感官写成可用。

## 5. 注意力与唤醒

工程关注刺激的新奇性、强度、变化与模型批准的 watch 条件。它只决定“让模型看看”，不替角色作出害怕/援助/换工作的决定。

`WatchCondition` 采用白名单：某类可感知信号出现、某已知对象进入视野、听见已知名称、计划阶段完成、模拟时间到点。禁止任意脚本、全局查询或“别人心里想什么”的条件。

建立 eventId 去重、进入/离开迟滞、持续事件合并。去重键只在内部使用；同一人同一事件不因观察 UI 每帧刷新而反复进入认知。

安全/基础身体事件不可被模型关闭。普通心跳不依赖外部刺激：到预约模拟时间就用自己的进度和状态作一次真实认知。模型批准的计划持续执行，直到下一认知明确继续/调整/中止。

世界冻结期间不得用真实时间继续采样感官，不能让同一 tick 因 API 等待过久重复心跳。

## 6. 主动感知动作

允许 `lookAt / turnHead / listenCarefully / approach / askClarification / readNotice`。这些都是有正模拟时长、受身体能力限制的动作。

模型调用“观察墙后”不能在同一冻结认知事务内移动摄像机替它看。应返回“需要先走到能看见的位置”，由模型提交走近动作；世界恢复且动作完成后，才提供新视角。

`recallMemory` 可以在屏障内查询自己的既有记忆，因为没有发生外部物理变化。但不允许它通过搜索世界日志获得从未经历的事件。

## 7. 私人记忆和信念

记忆类型：亲眼/亲耳经历、身体感受、自己的已执行行动、他人转述、个人推测、公开规则读后记录、摘要。每条带模拟时间、来源引用、可信程度和所有者。

“阿禾说仓库着火”是 `hearsay`；只有本人看见或通过其他合法证据确认，才能新增“我看见仓库着火”的直接经历。摘要不能把转述改成事实，也不能把不确定姓名升级成确定身份。

模型可以形成新的个人推测，但必须标为 belief 并引用可用线索；不引用凭空事件写亲历。代码检查所有者/来源存在性/类型，语义还需评测；不能声称 schema 校验消除了所有幻觉。

模型不需要输出或存储完整私密推理过程。保存可验证的决策、简短理由、承诺和事实/信念更新即可。开发者展示“决定的可解释摘要”，不包装成真实人脑意识流。

记忆遗忘、关系衰减和承诺到期都以模拟时间计。API 等待不产生“我站在这里想了二十分钟”的经历。

## 8. 保持世界内身份

身份提示使用世界内人物姓名、经历、能力和环境。禁止发送 API、token、barrier、simulation、NPC、player-camera 等运行元数据；技术协议字段通过网关外围 envelope 传输，不拼成世界描述。

提供窄工具集，不提供网络浏览、系统文件、调试控制台或环境时钟。HTTP 错误由观察者看，角色仍冻结，不把 429/timeout 改写成内心事件。

角色自然语言可能推测自己所处的世界，模型也可能生成跳出角色的话。工程能强制信息访问边界，不能保证模型永远不作这种推测，更不能声称它有真实人类主观体验。

对明显无依据的幕后系统内容采用角色一致性检查和有界重试；重试仍冻结世界。不要硬编码替换成预写台词。重试失败进入明确错误暂停，由观察者处理。

## 9. 感官具象化界面

### 9.1 模式与权限

- 关闭：游戏正常表现，无覆盖图。
- 单人：点击居民后显示此人的感官、已知线索、当前关注与最近触发原因。
- 全体概览：开发者可用，普通观察建议默认关闭，避免画面拥挤。
- 单人感知模式：隐藏或弱化该居民未感知的对象；这只是观察视图，不改变其实际知识。

主入口“感官”开关；子开关“视觉 / 听觉 / 身体信号 / 最近线索 / 最后已知 / 开发诊断”。支持触控操作，关闭面板不清空任何认知数据。

### 9.2 视觉覆盖

眼睛朝向箭头、视域扇形/截锥地面投影、近侧清晰区、外围模糊区、遮挡剪裁。部分遮挡可用网格或透明度表示；不要只有理想整扇形而未展示墙后失效。

对象标记区分“发现轮廓 / 看清外观 / 认出身份”。最后已知位置用虚线或幽灵标记与时间说明，不把当前真实位置伪装成记忆。

### 9.3 听觉覆盖

环形展示用户要求的听力具象化：使用一个指定“参考音量”的理想范围并在图例标注。现实可听范围还受声音大小、噪声与墙影响，不是万能固定半径。

可显示多圈参考：低声、普通说话、大声呼喊；实际声源产生以模拟时间扩散的波纹，遮挡损失/未达阈值区域用不同透明度。单人模式只展示此人实际听见的线索方向，不偷偷显示墙后真实说话者标签。

声音波纹是解释覆盖，不加入碰撞和视觉物体，不会被居民看见或听见。调试网格必须使用专用 render-only 层。

### 9.4 暂停与回放

思考期间居民扇形、身体、实际声音进度冻结；玩家可平移镜头、切换居民、开关覆盖层。回放用记录下的感官状态绘制，不能重新随机计算听清了哪些词。

打开/关闭覆盖层前后，模型输入 hash、模拟 RNG 状态和世界 hash 必须保持一致。绘图层不写模型状态、不消耗模拟随机数。

## 10. 信息隔离的验收原则

非干涉测试：两个世界只在某居民无法观察、也不影响其任何感官的隐藏部分不同，则该居民的输入 DTO 应相同。允许观察 ID 等已知非语义字段在规范化后比较；不得规范化掉真正的消息泄漏。

用受控场景分别改变墙后身份、隐藏库存、真实位置、其他人私人记忆、API 延迟、玩家镜头。检查传给模型的最终字节级 payload，而不是只检查模型最终有没有说出来。

工具报错、寻路失败、记忆摘要、项目工具也是泄漏面。测试不能只覆盖视觉一条路径。统计行为倾向属于后续评估，不能替代访问权限测试。
